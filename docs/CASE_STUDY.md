# 제조 스케줄링: 해법 구현부터 기술 선택까지

> 공개 벤치마크에 기반한 제약 최적화·강화학습 비교 프로젝트. 성능 향상을 주장할 수 있는 범위와, 추가 연구가 필요한 범위를 함께 기록한다.

## 프로젝트 소개

유연 잡숍 스케줄링은 공정의 순서와 가능한 설비를 동시에 고려해야 하는 조합 최적화 문제다. 본 프로젝트에서는 정적 최적화에서 출발해 납기와 일정 변경 비용을 추가하고, 고장·신규 주문에 대응하는 재계획으로 범위를 확장했다. 이후 학습 기반 정책이 기존 해법을 대체할 실익이 있는지 확인했다.

구현 범위는 데이터 검증, 제약 모델, 이벤트 시뮬레이터, RL 환경과 학습기, 실험 저장, 통계 분석, 독립 스케줄 검사, 대시보드까지다. AI 코딩 도구를 활용한 구현·문서화 프로젝트이며, 이 문서는 저장된 코드와 실험 결과에서 확인할 수 있는 성과만 기술한다. 실제 공장 운영 경험이나 검증되지 않은 개인 기여도를 덧붙이지 않는다.

## 설계 결정 1 — 강한 기준선부터 확보

초기 MK01에서는 CP-SAT이 최적 완료 시간 40을 찾았다. 따라서 RL을 도입하는 이유를 작은 문제의 성능만으로 설명할 수 없었다. MK01–MK10과 1·5·30초 예산으로 범위를 넓혀 규모와 계산 제한의 영향을 분리했다.

30초 제한에서 10개 중 5개 인스턴스는 모든 솔버 시드에서 최적성을 증명했지만, MK10은 고정 BKS 대비 평균 29.0% 차이를 남겼다. 이 결과는 최적화 해법의 계산 예산 의존성을 보여준다. 동시에 큰 문제에서 CP-SAT이 어려워진다는 사실만으로 RL 도입이 정당화되지는 않는다는 기준을 세웠다.

**관련 구현:** [정적 비교 실행기](../src/evaluation/run_expanded_static.py), [결과](../reports/expanded_results.md)

## 설계 결정 2 — 완료 시간과 납기 성능을 분리

같은 완료 시간을 가진 계획이라도 주문별 완료 시각은 다를 수 있다. 완료 시간만 최소화하는 해법에 납기지연을 추가해 실제 목적의 차이를 모델에 반영했다.

MK01·5초 예산·3시드 평균에서 완료 시간은 40으로 유지하면서 총 납기지연이 68에서 17로 줄었다. 감소율은 75%다. 일정 변경 비용을 강조하면 시작 시각 변경과 설비 교체를 줄일 수 있었지만 완료 시간과 납기 성능을 양보해야 했다.

이 수치는 합성 납기를 사용한 해당 조건에서의 성과다. 제조업 전체의 생산성 개선으로 확대 해석하지 않는다.

**관련 구현:** [다목적 CP-SAT](../src/algorithms/rolling_cpsat.py), [목적함수 프로토콜](../reports/expanded_experiment_protocol.md)

## 설계 결정 3 — 동적 문제에서 정보 누출과 실행 가능성을 통제

동적 재계획에서 중요한 것은 새 계획의 목적값뿐 아니라 기존 작업과 충돌하지 않는지다.

- 이미 시작된 작업을 고정해 과거 의사결정을 변경하지 않는다.
- 설비 고장 시 작업을 같은 설비에서 일시정지·재개하도록 정의한다.
- 신규 주문은 도착 시점 이후에만 관측에 포함한다.
- 방법별로 같은 외생 이벤트 tape를 사용한다.
- RL 정책의 합법 행동 마스크에 설비 상태와 공정 선후관계를 반영한다.
- 진행 가능한 작업을 무조건 선택하지 않도록 WAIT 행동을 제공한다.

현재 모델은 고장 발생 시 복구 예정 시각을 정확히 안다고 가정한다. 계산 중 시뮬레이션 시간도 멈춘다. 실제 현장의 복구시간 오차나 계산 지연으로 인한 실행 차질은 아직 모델링하지 않았다.

**관련 구현:** [이벤트 환경](../src/environments/event_fjsp.py), [재계획 시뮬레이터](../src/simulator/rolling.py)

## 설계 결정 4 — 학습 결과를 성공으로 포장하지 않기

추가 RL 비교에서는 PPO·PQN·GRPO-Sched·GSPO-Sched를 각 5개 시드, 65,536전이로 학습했다. 마지막 모델을 공통 36개 조건에서 평가하고, CP-SAT과 휴리스틱도 별도로 실행했다.

네 RL 구성 모두 시나리오 평균 비용에서 SPT보다 낮은 성능을 보였다. GRPO·GSPO와 PPO의 직접 비교에서도 명확한 우월성을 확인하지 못했다. 빠른 행동 추론만으로 품질 손실을 정당화할 수 없었고, 행동 한 번과 전체 재계획의 시간을 그대로 비교하는 것도 잘못된 해석이다.

GRPO·GSPO는 언어모델 학습 방법의 스케줄링 전용 변형이다. 다른 순차 의사결정에 적용하는 것은 가능하지만, 제조 스케줄링의 주요 비교 대상으로 삼은 도메인 근거는 부족했다. 이 실험은 탐색 결과로 보존하며 제조용 최신 대표 알고리즘 검증으로 주장하지 않는다.

다음 실험에서는 알고리즘의 발표 연도보다 상태 표현, 문제 구조, 학습 분포를 우선한다. 공정·설비 관계를 표현하는 모델이나 CP-SAT 해를 이용한 학습은 후보지만, 구현·효과를 아직 확인한 성과로 쓰지 않는다.

**관련 근거:** [4방법 결과](../reports/multi_rl_results.md), [사전 프로토콜](../reports/multi_rl_protocol.md)

## 문제 해결 — 결과를 다른 경로로 검증

시뮬레이터가 스스로 정상이라고 판단하는 것만으로는 구현 오류를 놓칠 수 있다. 저장된 스케줄을 읽는 별도 검사기로 다음을 재계산했다.

- 모든 공정의 존재와 중복 여부
- 설비 적합성 및 가공시간
- 공정 선후관계와 주문 도착 시점
- 설비 점유 구간 충돌 및 고장 구간 처리
- 이미 시작된 작업의 고정 여부
- 완료 시간, 납기지연, 정규화 목적값

추가 RL 비교에서 완료 스케줄 900개와 중간 계획 128개를 검사했으며 제약 위반은 없었다. 다만 솔버 응답 감사 경고 1건은 남아 있어 원본에 보존했다. 목적값이나 최적성 표시는 실제 계획 재계산과 구분해서 처리했다.

20개 체크포인트는 재로딩 후 동일한 검증 스케줄을 재현했다. JSON·CSV·PostgreSQL에는 같은 레코드를 적재하고 모든 셀을 대조했다. 이 검증은 해당 저장 결과의 정합성을 확인하는 것이며 모든 가능한 입력의 정확성을 증명하지는 않는다.

## 문제 해결 — 외장 파일시스템에서의 DB 오류

FAT32 외장 디스크에서 PostgreSQL 파일 쓰기 오류가 발생했다. 기존 파일과 백업은 로컬에 보존하고, DB를 tmpfs 기반의 재생성 가능한 조회 계층으로 바꿨다. 영구 원본은 프로젝트의 JSON·CSV로 유지했다.

재시작 시 원본을 DB에 다시 적재한다. 이 결정으로 모니터링 저장소의 생명주기와 실험 원본 보존을 분리했다. 공개 저장소에는 로그인 상태를 포함하는 Grafana SQL 백업을 배포하지 않으며, Grafana는 초기화와 provisioned dashboard로 구성된다.

## 포트폴리오 소개 문안

> **동적 제조 스케줄링 최적화 및 강화학습 평가 시스템**
> OR-Tools CP-SAT으로 공정·설비 제약과 납기·일정 변경 비용을 모델링하고, 고장·신규 주문에 대응하는 이벤트 기반 재계획을 구현했다. MK01의 제한된 실험에서 완료 시간을 유지하면서 총 납기지연을 75% 줄였다. 4가지 RL 구성을 5개 시드로 비교하고, 휴리스틱 대비 효과까지 검증해 현 설정에서 CP-SAT을 유지하는 기술적 판단을 도출했다. 추가 비교의 완료 스케줄 900개와 중간 계획 128개를 독립 검사하고, 원시 결과·통계·Grafana 조회를 연결한 재현 가능한 실험 체계를 구성했다.

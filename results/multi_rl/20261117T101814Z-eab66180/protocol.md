# Four-method masked RL comparison — frozen before outcomes

Primary comparison: MaskablePPO (SB3-contrib 2.9.2), MaskedPQN, GRPO-Sched, GSPO-Sched. Five seeds (0–4), exactly 65,536 environment transitions per seed. Last checkpoint is primary; no validation/test selection, tuning, early stopping, or favorable-seed exclusion. All trials run serially on CPU, one Torch thread, same host.

## Sources and implementation scope

- PPO: https://arxiv.org/abs/1707.06347 ; https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html — existing maintained MaskablePPO implementation.
- PQN: Gallici et al., *Simplifying Deep Temporal Difference Learning*, preprint 2024 / ICLR 2025, https://arxiv.org/abs/2407.04811 ; author's https://github.com/mttga/purejaxql ; reference https://docs.cleanrl.dev/rl-algorithms/pqn/ and https://github.com/vwxyzjn/cleanrl/blob/master/cleanrl/pqn.py . Independent PyTorch implementation of online parallel Q(lambda), with LayerNorm, no replay/target network, masked exploration AND masked bootstrap. Four environments / 128 steps, lambda .65, MSE, four epochs / batch128, Adam 2.5e-4 linearly annealed, gradient clip10, epsilon1→.05 during first half. Gamma1 preserves this task's undiscounted objective. CPU/Gym scheduling adaptation, not reproduction of pure-GPU Atari claims.
- GRPO: Shao et al., *DeepSeekMath* (2024), https://arxiv.org/html/2402.03300v3 sections4.1.1–2. GRPO-Sched uses the same-instance group-normalized final return, action-level clipped ratios, then a mean within each complete trajectory and across trajectories.
- GSPO: Zheng et al., *Group Sequence Policy Optimization* (2025), https://arxiv.org/html/2507.18071v2 equations5–7. GSPO-Sched clips exp(mean(log pi_new - log pi_old)) for each complete trajectory. It is NOT token-level GRPO renamed. Clip .0003 versus GRPO .2, reflecting the different ratio scales.

GRPO/GSPO are explicitly **scheduling adaptations**, not official supported scheduling implementations or reproduced LLM results. A scheduling trajectory replaces a language response. Group8 shares one generated instance and identical exogenous event tape; four instance groups per collection batch; four epochs, mini-batch8 COMPLETE trajectories. Population std, epsilon1e-8, constant-return group advantages0. No pretrained/SFT reference: beta=0; entropy bonus .01 is an explicit task-specific addition. No reward model; reward comes from the exact simulator objective. Policy loss weights trajectories equally despite unequal lengths. Actor architecture is two128 Tanh layers; PQN uses two128 LayerNorm/ReLU layers. PPO has an extra value network. Parameter/update counts recorded: this is a comparison of algorithm configurations, not a pure optimizer-only ablation.

## Data and fairness

All methods see identical observation fields, capacity260operations/15machines, legal-action mask and WAIT, objective -(makespan + mean tardiness)/100. Hidden future events remain inaccessible. No heuristic demonstrations or CP labels are provided to any RL learner.

Each training seed has a fixed128-instance bank at seeds2000000 + seed*1000 through +127, covering the same generated distribution as the previous pilot. PPO/PQN cycle through the same bank using four strided environments; group methods cycle four prompts with8 rollouts each. Visitation frequencies/number of unique episodes differ inherently and are logged. The finite bank differs from the old pilot's procedurally growing training stream, so the old pilot is historical context, not the matched control. PPO is retrained here.

Validation: seeds9000000–9000003; previously inspected development data, curves only. Fresh generated tests: seeds9200000–9200019 fixed before training; 10static/10dynamic by parity. External transfer: MK01–MK10 plus MK01/MK06 combined event seeds0–2; these already inspected benchmarks are not new blind tests. All36 full specifications saved before training. All methods evaluated deterministic greedy once per instance per training seed. CP-SAT1/5sec balanced and SPT/EDD/MWKR recomputed on the same evaluation specifications after RL training.

Every environment transition counts, including all8 group members. At the exact step cap, incomplete same-instance groups are excluded from optimization; all their collected transitions remain counted and unused_transitions is reported. PPO/PQN caps divide their rollout sizes exactly. Group validation occurs at first completed batch crossing each16384 interval, at actual logged steps, plus exact final step. No interpolation or smoothing. Initial validation recorded for every trial.

## Measurement and audit

Primary quality is (makespan + mean tardiness)/100, lower better. Pair each RL instance against CP5 and PPO within each training seed; average instance-relative gaps per scenario per seed, then report mean and t95% intervals across5 training seeds. These intervals describe seed variability, not independent industrial sites. Also report per-instance wins/ties/losses, raw quality, latency per action AND full episode, training elapsed time (includes periodic validation/recordIO/checkpoint saving), parameters, memory, update count and unused transitions. No formal superiority claim from this fixed-budget pilot.

Schedules are independently audited from saved JSON for eligibility, precedence, duration under outages, releases and machine overlap. Checkpoint reload must reproduce full deterministic validation schedule exactly. Save complete configuration, source hashes, training bank visitation, raw training/validation/test records, optimizer/RNG at final checkpoints, SHA256 and DB/CSV roundtrip audit. Custom-method resume is between completed seeds; interrupted custom trials restart rather than claiming exact mid-trajectory resume.
